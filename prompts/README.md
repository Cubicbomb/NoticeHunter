# prompts/ — 关键 Prompt 留档

**这是评分项，不是可选记录。**

竞赛通知原文要求项目文档末尾附上「AI 工具使用、**关键 Prompt**、生成或开发过程、迭代优化、测试验证和人工核查情况」。预赛评分第一项「学术诚信与 AI 使用规范」占 12.5%，本目录就是这一项的原始证据。

## 三条铁律

1. **只增不改。** 记录写错了不要回头改，新增一条说明修正（这也是真实的迭代过程，本身就是加分素材）。
2. **Prompt 原文原样粘贴。** 禁止润色、禁止翻译、禁止"整理成通顺句子"。保留你当时的错别字和口语表达——那才叫过程记录。
3. **从第一天开始记。** 不要攒到最后一周补写，补出来的东西时序和细节都对不上，看得出。

## 命名与编号

- 文件名：`P-001-通知结构化抽取.md`，编号连续，不复用、不跳号。
- 一条记录 = 一次有意义的尝试。纯粹的错别字重试不用记，**但选错工具、改错方向、加了约束条件这种要记**。

## 记录格式（直接复制）

```markdown
# P-000 · 一句话标题

- **日期**：YYYY-MM-DD
- **工具**：具体工具与模型名（如 MiMo Desktop / DeepSeek-V3、通义灵码、Coze）
- **环节**：对应闭环的哪一步（如：结构化抽取 / 冲突检测 / 界面文案生成 / 代码生成）
- **输入**：用了什么素材（路径或描述，如 prototype/samples/notice-01.docx）
- **上游**：若是基于上一版 Prompt 改进，写编号（如 P-002）
- **状态**：采用 / 废弃

## Prompt 原文

（原样粘贴，用代码块包起来，不要做任何美化）

## AI 输出（关键片段）

（只留能说明效果的片段，不要整段贴）

## 观察

- 成功：这一版哪里对了
- 问题：哪里漏了、错了、格式不稳（具体到字段或样例）
- 人工核查：这一轮人工核对了什么，发现了什么 AI 的错误

## 下一步

（下一条编号打算怎么改）
```

## 关于人工核查（评分明确点名的一项）

每条记录里的「人工核查」不是走过场。真实做法举例：

- 逐条比对抽取结果与原文，记录错了几条、错在哪类字段；
- 模糊时间（「下周三」「本周内」）是否被错误换算成绝对日期；
- 是否把不同文件里同一个 deadline 误判成两件事。

**把这些错误如实写下来。** 主动暴露 AI 出错并说明人工如何兜住，比假装一次成功更符合"符合 AIGC 应用特色"的评审口径，也更可信。

## 给接手智能体的提示

新接手时先读本目录最后 3 条记录，能快速了解：当前 Prompt 已经试到哪一版、哪些方向已被证否、还有哪些问题没解决。**不要重复已被否定的尝试**；若要推翻某条结论，在 `HANDOFF.md` 决策记录里新开一条并引用编号。
