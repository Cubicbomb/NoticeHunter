## [S1] What & Why

### 来源

不是新想法，是 **D-008 明确顺延**的两项，`HANDOFF.md` 待办里标注了「勿丢」：

- **deadline 汇总**：按日期聚合已确认条目、倒计时天数、同日分组、最近截止优先。
- **交互优化**：待确认卡片计数与状态筛选、丢弃可撤销、待确认与清单分屏减少来回滚动、原文区可展开。

本轮开工依据是决策 **D-011**（用户 2026-10-16 对 R-13 / R-14 / R-19 三问统一回答「先完成项目开发」，把材料与团队事项后置）。

### 为什么值得做

1. **汇总正是本作品对用户承诺的那一半。** `D-002` 写的痛点是「多个通知的截止时间互相冲突，**无人汇总**」。当前实现里，清单只有按时间升序的一条条流水（`confirmedItems()`），用户仍要自己从上往下扫一遍才知道「接下来该盯哪天」。**汇总视图缺位，等于痛点只解决了一半。**
2. **原文区与待确认区的滚动成本随文档长度线性上升。** 实测样例有 42 段，单份真实通知会更多；「找一条待办 → 回原文核对 → 再滚回清单」是当前最费时的动作，也是 20%「完整与实用性」的直接扣分点。
3. **丢弃不可撤销是数据事故。** 一次误点就丢一条抽取结果，而抽取可能消耗了 AI 预算（S2.11 计了费）。**付过钱的东西不该因为一次误点永久消失。**

### 与四道差异化设计的关系

四道设计（只输出动作、出处高亮、低置信度强制人工确认、跨文件去重撞期）**一条都不改**。本 spec 只在其之上加一个结果视图与四点可用性修补，属于「在既有约束之上再加一层」，与 `noticehunter-llm` 的 S2.11 同构。

## [S2] 行为契约

### S2.1 截止日汇总视图

新增第 5 个 `section`，标题 `按截止日汇总`，包含两个区块：

- `#deadlineStats`：统计条，一行文字。
- `#deadlineList`：按日期分组的列表。
- `#deadlineEmpty`：空态提示（无已确认条目时显示）。

**聚合规则**：

1. 数据源为 `confirmedItems()`（`status` 为 `confirmed` 或 `done`），与行动清单同源，**不得另起一套状态**。
2. 每条的日期取 `it.due` 的前 10 位，且必须匹配 `^\d{4}-\d{2}-\d{2}`；匹配不到的进「截止时间模糊」组。
3. **分组按日期升序**（最近截止优先），**模糊组固定排最后**。
4. 每组显示：日期、倒计时标签、该组条目数、该组条目清单（截止时间 / 动作 / 谁 / 出处）。

**倒计时标签**（相对**本地今天零点**的整日差，不是时间戳差）：

| 差值 | 标签 |
| --- | --- |
| `< 0` | `已逾期 N 天`（加警示样式） |
| `= 0` | `就是今天` |
| `= 1` | `明天` |
| `2..30` | `还有 N 天` |
| `> 30` | `还有 N 天`（不另做降级） |

**统计条**必须同时给出三个数：已确认总数、**最近的一个未完成截止日及其倒计时**、**未完成且已逾期的条数**。逾期统计**排除 `done`** —— 已完成的任务不该被算作逾期，否则用户一勾完反而指标变差。

### S2.2 待确认区计数与筛选

`#reviewFilter`（新元素，位于 `#reviewList` 之上）：

- 计数文案：`待确认 N 条 · 低置信度 M 条`，N 为**全部** `pending` 数，M 为其中 `confidence === 'low'` 数。筛选不改变 N、M（它们描述全量，不随筛选变化）。
- 筛选按钮三个：`全部` / `低置信度` / `高置信度`，分别对应 `state.reviewFilter = 'all' | 'low' | 'high'`，默认 `'all'`。
- 当前项加 `aria-pressed="true"` 与可见的选中样式。
- `renderReview()` 按 `state.reviewFilter` 过滤后再渲染；空结果时给出对应的空态文案（不是通用空态，要说明「当前筛选下没有条目」）。
- 筛选**只影响待确认区**，不影响清单、汇总、去重与确认逻辑。

### S2.3 丢弃可撤销

- 丢弃时记录 `state.lastDiscard = it.id`，随后 `status = 'discarded'`。
- `#undoDiscard`（新按钮）：仅当 `state.lastDiscard` 指向一条真实存在的 `discarded` 条目时可用，否则 `disabled`。
- 点击撤销：把该条 `status` 改回 `'pending'`、清空 `state.lastDiscard`、`toast('已撤销丢弃')`、`renderAll()`。
- 撤销后的条目回到**待确认区**并保持原有 `confidence` / `reasons` / `extractor` 不变。
- **只撤销最近一次**；连续丢弃多条后只能撤回最后一条（明确边界，不做栈，避免做成历史记录面板）。
- `清空会话` 必须一并清空 `state.lastDiscard`（否则会话清空后还能"撤销"出上一个会话的条目）。

> **为什么撤销按钮放在待确认区，而不是做进 toast**：现有 `toast()` 用 `textContent` 写入，消息里含**用户自己的文件名**（`'已载入 ' + src.name`）。若为加按钮改成 `innerHTML` 拼接，等于把文件名变成注入点（文件名可含 HTML 字符）。**不为了一个按钮改掉原有的注入面**，因此撤销入口做成常驻按钮。

### S2.4 待确认与清单分屏

- 把第 3 节与第 4 节包进一个 `div.split` 容器。
- **≥1080px**：两列（`minmax(0,1.05fr) minmax(0,0.95fr)`），`.wrap` 最大宽度由 900px 放宽到 1180px，减少左右两栏来回滚动。
- **<1080px**：保持单列纵向排布，**与改动前的窄屏体验完全一致**。
- 两栏 `align-items: start`，避免强制等高把短栏拉长。

### S2.5 原文区可展开

- `state.rawExpanded`，默认 `false`。
- 折叠态下，**每份来源只渲染前 `RAW_PREVIEW_COUNT = 6` 段**，其后给出「展开全文（本份共 N 段）」按钮。
- 展开态渲染全部段落，按钮变为「收起原文」。
- **关键约束（否则会打断现有出处高亮）**：当 `state.highlight` 指向的段落**超出折叠预览范围**时，`renderAll()` **必须自动按全文渲染**——否则 `jumpTo()` 找不到 `.para.hl`，「点出处 → 原文高亮」这条差异化设计会被静默打断。
- 切换折叠不改变 `state.highlight`，因此收起/展开后高亮仍保持。

### S2.6 不变的部分

- 规则式抽取、LLM 主抽取与 S2.11 五项硬上限（`max_tokens` / 单段截断 / 60 次预算 / 800ms 间隔 / 200 段确认）**全部不动**。
- 去重与撞期判定（`dedupKey` / `computeConflicts`）**不动**；汇总视图只读它们的产物。
- 导出（`buildExport`）内容**不变**，汇总视图不进导出文本。
- 零依赖、断网可跑、`file://` 直开**不变**；本 spec 不引入任何 npm 包。

## Report

**What was built** —— 在**不改动**四道差异化设计、不改动 S2.11 五项硬上限、不引入任何 npm 包的前提下，补上 D-008 顺延的两块：

1. **按截止日汇总（新增第 5 节 `按截止日汇总`）**：新增 `renderDeadline()`，**只读 `confirmedItems()` 的产物**（清单同源，不另起状态）。按 `due` 前 10 位分组并**升序**排列（最近截止优先），无匹配日期的条目归入「截止时间模糊」组且**固定排在最后**；每组显示日期、倒计时标签、条目数徽章与条目明细。顶部统计条同时给出三项：已确认总数、**最近一个未完成**截止日及其倒计时、**未完成**逾期条数。倒计时按**本地日期零点差**计算，标签取值为 `已逾期 N 天 / 就是今天 / 明天 / 还有 N 天`。
2. **四项交互修补**：① 待确认区顶部计数 `待确认 N 条 · 低置信度 M 条` + `全部 / 低置信度 / 高置信度` 筛选（`state.reviewFilter`，只影响待确认区）；② `撤销上次丢弃`（`state.lastDiscard`，**只回溯最近一次**，清空会话一并清掉）；③ 第 3、4 节包进 `.split`，**≥1080px 两列**、<1080px 保持单列；④ 原文区默认每份来源只渲染前 6 段，`#rawToggle` 切换，**高亮落在预览之外时自动展开全文**。

**Verification** —— `node --check` 对提取出的内联脚本与两个验收脚本全部通过。两套浏览器验收在**主目录 `main` 工作树**上实跑：`node prototype/verify.cjs` **60 PASS / 0 FAIL**（原 30 条全数保持 + 新增 30 条 D-008 断言）；`node prototype/verify-llm.cjs` **69 PASS / 0 FAIL**（未回归）；**合计 129 PASS / 0 FAIL**。新增断言里**没有任何一条写死运行当天的天数**——日期相关一律用注入的固定日期（`2000-01-01`，永远在过去）或差值断言，换个日期跑不会红。

## Journey log

1. **新增 UI 会静默改变旧测试的前提。** 原文区一折叠，`T2 .docx 解析出正文` 与 `T9 file:// 直开` 立刻变红——不是解析坏了，是正文落在第 7 段之后、折叠态压根没渲染。「既有 30 条必须保持 PASS」这条验收，**不真跑是绝对看不出会挂的**。
2. **撤销入口为什么不放进 toast。** `toast()` 用 `textContent` 写入，而消息里含**用户自己的文件名**（`'已载入 ' + src.name`）。为了加个按钮改成 `innerHTML` 拼接，等于把文件名变成注入点。所以撤销做成待确认区的常驻按钮——**不为一个交互去动掉原有的注入面**。
3. **倒计时用日期零点差，不用时间戳差。** `(target - today) / 86400000` 在跨夏令时的边界上会算出 `-0` 之类脏值；先各自取零点再 `Math.round` 才稳。
4. **逾期统计排除已完成。** 否则用户把任务一勾完，「已逾期 N 项」反而不降，**把完成变成了负反馈**。这一条有专门断言守着（总数不变、逾期数 −1）。
5. **高亮必须能穿透折叠。** 折叠上限 6 段，而出处常指向第 12、22 段；不自动展开，`jumpTo()` 就找不到 `.para.hl`，**「点回原文高亮出处」这条差异化设计会被静默打断**。因此就地把 `rawExpanded` 提为 true，而不是造一个「看似收起、实则展开」的二义状态。
6. **日期断言写死「还有 70 天」= 换天就全红。** 改成断言**标签格式**与**分组排序关系**，再用注入的 `2000-01-01` 制造确定的逾期场景。
7. **测试前置条件不能依赖样例分布。** 第一次跑在 T8 崩掉（`Timeout 30000ms exceeded`）：我自己的 T6 步骤刚把低置信度 pending 全清成 discarded，剩下可丢弃的条数取决于样例怎么写。改成**注入固定条目 + 条数不足时记 FAIL 而不是让 harness 崩**——harness 一崩，前面所有结果都打印不出来，等于白跑。
8. **两次编辑失误都是 `node --check` 抓住的**：一次替换误删了 `renderModeBadge` 的 `const conf = llmConfigured();`（会变成运行时 `conf is not defined`），一次把注释的闭合符切掉了。**改完就 `node --check`，不要靠眼睛看。**
