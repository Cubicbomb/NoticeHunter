# 通知猎人 NoticeHunter · MVP

> 路径覆盖说明：`compose-next` 默认 spec 路径为 `docs/compose/spec/<feature>.md`；项目 `AGENTS.md` 未规定 spec 路径，故沿用默认位置。

## Report

## [S1] Problem

学生一学期内会从学院通知、竞赛公告、课程大纲、老师群聊等多处收到截止时间要求，彼此独立、互不汇总，也没有任何工具把它们变成一份可直接照做的清单。现有笔记类工具需要手动抄写，且**无法跨文件识别同一截止时间的重复项，也无法发现同日撞期**。漏掉一件就是一次事故。

本功能解决的是「从信息到行动」这最后一步：把零散通知转成「谁 / 什么时候前 / 交什么 / 交到哪」的可执行清单。

## [S2] Design

### S2.1 交付形态

- 单文件 `prototype/index.html`，HTML + CSS + JS 全内联，**零构建、零 npm 依赖、零外部网络请求**。
- 可从 `file://` 直接双击打开，也可用 `python -m http.server` 起服务访问；两种方式表现一致。
- 界面文案中文。
- 内置样例文本以 JS 字符串常量内联，**不得用 `fetch()` 读取**（`file://` 下会失败）。

### S2.2 会话与数据模型

一个页面实例 = 一个会话，可依次载入多个文件。核心结构：

```
TodoItem {
  id            : string            // 会话内唯一
  sourceName    : string            // 文件名
  sourceIndex   : number            // 该文件内的段落序号，1-based
  sourceText    : string            // 原文段落，用于出处高亮
  action        : string            // 交什么 / 做什么
  owner         : string | null     // 谁；无法识别则为 null
  due           : string | null     // 归一化截止：YYYY-MM-DD 或 YYYY-MM-DD HH:mm
  dueRaw        : string | null     // 原文时间表述，原样保留
  confidence    : 'high' | 'low'
  reasons       : string[]          // 低置信度原因，供界面展示
  status        : 'pending' | 'confirmed' | 'discarded' | 'done'
  mergedFrom    : number            // 合并来源数量，默认 1
}
```

`status` 状态机：`pending → confirmed → done`，或 `pending → discarded`。**只有 `confirmed` / `done` 进入行动清单。**

### S2.3 输入与解析

| 输入 | 行为 |
| --- | --- |
| `.txt` | 按换行切段，空行丢弃 |
| `.docx` | 手写 ZIP 解析 + 浏览器原生解压，见 S2.4 |
| 内置样例 | 点击「用样例演示」载入内联文本，等价于拖入文件 |
| 多文件 | 依次载入同一会话，段落统一编号并保留各自 `sourceName` |

段落切分后统一进入抽取器。单个文件解析失败只影响该文件，不影响已载入内容。

### S2.4 `.docx` 零依赖解析契约

`.docx` 本质是 ZIP。**禁止引入任何库**，按下列顺序实现：

1. 读 `File` 为 `ArrayBuffer`。
2. 从文件末尾向前扫描 EOCD 签名 `50 4B 05 06`，读取中央目录条目数与偏移。
3. 遍历中央目录条目，定位 `word/document.xml`，记录其压缩方式（`0` 存储 / `8` deflate）与本地头部偏移。
4. 读本地头部取到数据起始位置，取出压缩字节。
5. 压缩方式为 `8` 时，用 `new DecompressionStream('deflate-raw')` 解压为文本；为 `0` 时直接按 UTF-8 解码。
6. 对 XML 剥标签：`</w:p>` → 换行，`<w:tab/>` → 空格，其余标签删除，再还原 `&amp; &lt; &gt; &quot; &apos;`。

**错误行为**：找不到 EOCD、找不到 `word/document.xml`、解压失败、解出空正文——任一情况都抛出带中文说明的错误，由界面 toast 呈现，**页面不得白屏或抛未捕获异常**。

### S2.5 规则式抽取

对每个段落独立抽取，输出 0..n 条候选 `TodoItem`。规则全部为确定性正则/字符串匹配，**不调用任何模型**。

**截止时间**

| 类型 | 匹配 | 结果 |
| --- | --- | --- |
| 完整日期 | `YYYY 年 M 月 D 日` / `YYYY-MM-DD` | `due` 归一化，置信度可为 high |
| 补时间 | 上述后跟 `HH:mm` | `due` 带时间 |
| 缺年份 | `M 月 D 日` | 按当前年推算，**强制 low**，reason 记「原文未写年份」 |
| 模糊表述 | 本周内 / 本周 / 下周 / 下周一之前 / 近期 / 尽快 / 一周内 / N 日内 / 考试结束后一周内 | `due = null`，**强制 low**，reason 记「截止时间表述模糊」 |
| 截止标记 | 日期后出现 `前 / 之前 / 截止 / 截止时间` | 认定为截止时间；若无此标记则记 reason「未明确标注截止」并置 low |

**动作（交什么 / 做什么）**

取包含截止时间的那个句子（或编号列表项 `1.` `(1)` `一、` 的项文本），剥离时间表述与截止标记，剩余文本作为 `action`。剥离后为空则退回整句去时间文本。

**交到哪**

匹配 `交至 / 交到 / 送至 / 提交至 / 提交到 / 上传至 / 发送至 / 交于 / 上传到` 之后直到标点的片段；邮箱用 `[\w.+-]+@[\w.-]+\.\w+` 单独识别。

**谁**

匹配 `各班级 / 各学院 / 全体 / 各位同学 / 请各…` 等，映射为概括标签（如「全体本科生」「各班学习委员」）；无匹配则 `owner = null`，界面显示「待分配」。

**置信度**

- `high`：有具体日历日期（非模糊表述）且含年份。
- `low`：命中任一模糊表述、缺年份、或段落内无任何交件动词。

### S2.6 人工确认节点

- 所有候选进入「待确认」区，**未确认不得进入行动清单**。
- `confidence === 'low'` 的卡片整体标黄，并逐条展示 `reasons` 作为原因标签。
- 卡片上四个字段（动作 / 谁 / 截止 / 交到哪）可直接编辑，编辑后可再次确认。
- 每张卡片提供「确认」与「丢弃」两个操作。
- `high` 的卡片默认勾选但仍需用户点确认——**不让程序替人拍板**。

### S2.7 跨文件撞期与去重

- **去重**：两条已确认条目的 `action`（去空白与标点后比较）与 `due` 完全一致时合并为一条，`mergedFrom` 累加，卡片标注「合并自 N 个来源」。
- **撞期**：对所有已确认条目按 `due` 的日期部分（`YYYY-MM-DD`）分组；任一日期下条目数 ≥ 2 时：
  - 界面顶部出现提示条：`同一天有 N 个任务：YYYY-MM-DD`，逐日期列出；
  - 相关卡片加上撞期标记。

### S2.8 行动清单

- 仅含 `confirmed` / `done` 条目。
- 排序：`due` 升序；`due` 为 `null` 的排在最后，按载入顺序。
- 每条含：完成复选框、截止、动作、谁、交到哪、撞期/合并标记、「出处」按钮。
- 勾选 → `status = done`，行内加完成样式（删除线 + 降透明度）。

### S2.9 出处跳转

- 点击某条目的「出处」→ 原文区滚动到 `sourceIndex` 对应段落并高亮；再次点击其他条目时高亮切换。
- 高亮同时在原文区显示来源文件名与段落号。

### S2.10 导出

纯文本，通过 `Blob` + `a[download]` 下载为 `.txt`，同时提供「复制到剪贴板」。

```
【通知猎人 · 行动清单】生成于 YYYY-MM-DD HH:mm

[ ] 2026-11-05 17:00  提交毕业实习鉴定表等材料
    谁：全体毕业生
    交到：学院学生事务办公室（示例楼 A301）
    出处：notice-internship.txt 第 12 段（合并自 2 个来源）

[ ] 截止时间模糊  缓考申请提交
    ...
```

- `due` 为 `null` 时该行显示「截止时间模糊」并保留原文表述 `dueRaw`。
- `status = done` 的条目复选框显示为 `[x]`。

### S2.11 错误与边界行为

| 情况 | 行为 |
| --- | --- |
| 非 `.txt` / `.docx` 文件 | toast：「暂不支持该格式，请上传 .txt 或 .docx」，不载入 |
| 损坏的 `.docx` | toast 带具体原因，不载入，不影响已载入内容 |
| 解析出 0 段正文 | toast：「文件已读取，但没有解析出正文段落」 |
| 未确认就导出 | 允许导出，但仅含已确认条目；清单为空时提示「还没有已确认的行动项」 |
| 刷新页面 | 会话清空（**不做本地持久化**），文案中说明 |

所有错误路径都必须可恢复，**任何情况下页面不得白屏或抛出未捕获异常**。

### S2.12 界面结构

单页自上而下：产品名与一句话定位 → 输入区（拖放 + 文件选择 + 样例演示）→ 原文区 → 待确认区 → 行动清单区。冲突提示条固定在清单区上方。断网可用状态在头部以徽章标明。

## [S3] Out of Scope

明确不做，避免范围蔓延（`AGENTS.md` 第 4 节：材料 > 功能）：

- **任何大模型 / API 调用与网络请求**。MVP 只做规则式抽取，LLM 接口留到下一迭代。
- PDF 解析、图片 OCR。
- 日历导出（`.ics`）、多人分工视图、提醒推送。
- 本地持久化（`localStorage`）。
- 移动端专门适配（保证不横向溢出即可，不追求体验）。
- 账号体系、后端服务、云存储。
